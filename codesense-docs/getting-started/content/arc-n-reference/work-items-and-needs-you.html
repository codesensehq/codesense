Work items, launchers and what needs you

Every agent session belongs to one piece of work, records who launched it, and anything that waits on you is counted once, from one set.

Work items

A work item is the one piece of work a lead launch starts. Its id is wi_ followed by 16 lowercase hex digits, for example wi_3f9a0c41d27e88b5. Every agent session below the lead shares it; a plain shell has none.

  • An agent launched by a person, the Foreman, a routine, or an agent outside any work item gets a new work item, and so does each routine run.
  • An agent launched by a session that has a work item joins that work item.
  • A session restored after a restart keeps the work item it had and never gets a new one.
  • A plain shell never has a work item, even when an agent opens it.

Today the work item is carried by two records: the session record, and the record of a context worktree that a launch creates, together with its lead's session and agent. A worktree that is reused keeps what it has. Neither list_sessions nor the agent tree shows or groups by it yet; grouping by work item comes later.

What launched_by records

Launch launched_by
A person, from the launch sheet, ⌘K or a dashboard empty
The Foreman, or a durable dispatch empty (the session gets its own work item)
An agent launching a worker the launching session
An agent opening a tab with open_terminal_tab the calling session (a launcher already recorded is never overwritten)
A routine run routine:<key>, the same id its queue uses
A restore after a restart the original launcher, unchanged; a relaunch after a restart also records restoredBy: "CodeSense restore"

A launched_by filter matches a record with the same text. A record saved in the older routine <name> form also matches a routine:<key> filter when the last part of the key is the name as a slug: routine Steward weekly matches routine:acme/ops/steward-weekly.

The needs-you set

Everything that waits on you is one set, derived in one place. Each item has a kind:

Kind When
question An unread needs-you Inbox card that is not a merge card, or an agent's open question
permission An agent waiting on a permission ask
merge An Inbox card that names a PR and offers to merge it or send it back
capped An agent paused at a spend cap
failed An agent that failed or crashed

FYI cards never count, and neither do read, withdrawn or archived cards. Each item also carries the session it is about and its org, team and workItem, so a team's or a work item's view is the set narrowed by those fields.

Where to read it

  • The live needsYou topic publishes the set, scoped by team, and updates on the same events that change it, so there is nothing to poll.
  • codesense_overview has a needsYou section with its total, its count byKind and its items.
  • The Inbox's counts row counts the set's cards per sender; a sender with none drops out.
  • Routine runs that ended waiting on you are not items of the set. The overview reports them as runsAwaiting, and the Schedule row reads "N runs waiting".
