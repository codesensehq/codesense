# Changelog

All notable changes to CodeSense are written here, for the people who use it.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and CodeSense uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Until 1.0, a minor release (0.x.0) may change or remove things you rely on. When one does, its entry says so under "Changed" or "Removed".

## [Unreleased]

## [0.1.1] - 2026-11-23

CodeSense 0.1.1 is the first update since launch. It adds pinned live views and GIF search in agent chat, the Foreman setup agent, rendered diffs for images and documents, and a refreshed chat overlay. It also lowers idle CPU, keeps machine saves from overwriting newer edits and fixes many small rough edges.

### Added

- **Pinned views in an agent's chat.** Agents and dashboards can pin up to three live views to an agent's chat with `inbox.pin` or the MCP `pin` tool; the pins survive a restart, and a headless run no longer offers a chat it can't open.
- **Agents can search GIPHY for a GIF to send.** The new `gif_search` tool uses your own GIPHY key, which you add in the new Settings → Messaging section, where you can also turn GIF search off and set the rating ceiling (PG by default).
- **Agent skill allowlist.** An agent's new `skill_allowlist` limits the skills a Claude launch offers, context worktrees included. It turns off every other skill the agent's startup places or the workspace's `.claude/skills/` holds; personal (`~/.claude/skills/`) and plugin skills stay on. A `skills` key in agent.yaml is not this field and still does nothing.
- **An agent thread is keyed by the saved agent, whatever its revision.** A thread is keyed by the saved agent (the id before `@`) and the story, so every caller, a session or a page or a person naming `agent@4`, reaches the same thread. A session on a new revision of the same saved agent therefore opens that thread, appends to it and keeps its pins. Another story, or a session with no story, keeps its own thread.
- **An agent thread reads every session of it.** The app reads the messages of a saved agent's thread on a story across its sessions, an ended predecessor's included, so a successor opens on what came before; another session of that agent running at the same time keeps its own conversation.
- **arm64 Linux AppImage.** Linux test builds for arm64 now include an AppImage beside the `.deb` and `.rpm`.
- **A seat's cost follows the story it works on.** `charge_session_story` charges a session to a story from a moment on, so `session_usage` lists a seat that worked several stories as one row per story segment (with its launch's `tabSessionId`), and story totals cost each story from its own segments.
- **The chat on a terminal tab shows Queued and Delivered.** What you send an agent from its overlay is marked Queued while the agent is busy and has not yet been told, and Delivered once it has, by the kit chat's shared rule. The kit chat also ships its own stylesheet (`/kit/v1/chat.css`, linked by `chat.js`, or off with `styles: false`), and two chats on one page no longer share element ids: the first keeps the plain ids, later ones carry `-2`, `-3`.
- **Pin any chat message yourself, with Undo.** In an agent's chat overlay, in the Inbox (where a conversation is one agent's thread) and on pages that mount the kit's chat (`onPin`), each message has a Pin in its action row; an HTML message has it in its title bar. Your pin previews the message (a quote, or the page's name) next to the agent's pins. The 3-pin cap is shared with the agent: at the cap every Pin is dimmed and says whose pins fill the list, and nothing is replaced. Unpinning offers Undo, which puts the pin back as it was through the new `restorePin` verb (or the `pin` tool's `restore` flag).
- **Claude agents take a bridge tool list.** `mcp.bridge_tools` now applies to Claude agents: each left-out CodeSense tool is denied by name, `signal_done`, `read_messages` and `reply` always stay, and the agent's server instructions leave out the tools it can't call.
- **clone_repo.** A new MCP tool checks a repo name and folder, runs `git clone` in a visible terminal tab with no shell, and binds the clone to a team's source repo. It needs no GitHub CLI and never stops at a password prompt, and it only clones into a folder under your home folder.
- **`onSessionText` streams a Codex session too.** A page can hear a running local Codex session's reply as it is written, the same way as a Claude session's: its assistant prose as each item lands, then one final message per turn. Reasoning, tool calls, tool output and the injected project instructions are never sent.
- **The Foreman opens when CodeSense starts.** Its page opens as one tab and is focused if it is already open, with or without a context repo of your own; turn it off with "Open the Foreman when CodeSense starts" in Settings, and the identity menu and ⌘K bring it back any time.
- **The chat overlay on the Foreman's tab says when its setup is running.** While the Foreman page hosts a setup session, the overlay shows "Setup is running" with Open full view, which opens the Foreman's tab, where setup's messages and questions are.
- **The Foreman page ships in the docs bundle.** It is the page the app will open for the Foreman, built from the story view kit with a public config and checked against the page hash that lets it launch the Foreman in a team's workspace; it only starts the Foreman and its setup guide, and nothing opens it on start yet.
- **GIFs say where they come from.** A GIPHY GIF in the Inbox shows "Powered by GIPHY", a KLIPY GIF says "via KLIPY" in the enlarged image, and a GIF whose media is off says so instead of offering Load.
- **Core setup steps.** The setup guide can now create or connect your context repo, create your team and a setup log, name your product and add your source repos, each after one consent card.
- **First story step.** After your repos are cloned, the setup guide offers `Start my first story`: it writes one story for a repo your team tracks after a consent card, checks it first, and opens it. A new story never changes one you already have.
- **Git access and clone steps.** The setup guide now asks how agents should reach your git host (any method, never requiring `gh`), checks it with one read, saves `tools/git-access.md` to your team, and clones your tracked repos in visible terminal tabs after one consent card.
- **CodeSense setup agent.** A `codesense-guide` pack holds the setup agent for Claude, Codex and OpenCode and its `/codesense-setup` command, which replaces the old example skill of the same name.
- **The CodeSense setup page.** A bundled docs page mounts the shared chat (`kit.chat`) in its page layout for the setup guide: consent cards that show their class, suggested prompts from the agent's `Next:` line, an activity line and Stop, a runtime chip with the installed CLIs, a `⋯` menu (what I've set up, copy the setup summary, clear the conversation), an empty state when no agent CLI is installed and a sign-in notice with the CLI's own login command. The guide's messages the page shows are marked read, so they don't pile up unread in the Inbox. Its hash joins the pages that may open a team agent (`guide-claude`, `guide-codex` and `guide-opencode` may now be launched by those pages), and the guide pack asks for `kit.chat` version 1.
- **`kit.chat` can read a consent card line.** `cards: { consent: true }` reads the `card: <step> · <class> · <act>=<label> | …` line that ends a card's text into the card's buttons, its consent class in the header and `data-step`/`data-act` attributes, and hides the line; `core.parseCardLine`, `core.formatCardLine` and `core.CONSENT_CLASSES` (also exported from the overlay's `chat-core`) hold the one format. Off by default.
- **`kit.chat` can show each sender's avatar, with one meta line per run.** The new `faces` option (`true`, or `(row) => { src | face, name, label }`) puts the sender's avatar, through `kit.avatar` or an image, at the start of a lead's or another agent's run of messages, and a run from one sender shares one meta line. Off by default; unset, the thread is unchanged.
- **A page can open an HTML message in its kit chat.** A page that mounts the kit chat with `html.open` gets an Open on each HTML message: the page shows the message under its name, and Close (or the message leaving, or the chat closing) releases it. Pages that don't pass `html` are unchanged.
- **`kit.chat` can turn an agent's trailing `Next:` line into suggestion chips, with an edit pencil.** `core.parseNext` (also exported from the overlay's `chat-core`) reads the line, the new `next` option shows its chips after the agent's newest message and leaves the line out of the text, and a chip's pencil puts its text in the composer to edit before sending (`next: { edit: true }`, or `edit: true` on a `chips` entry). All off by default.
- **`kit.chat` can lay out as a full page and show a working row.** `layout.variant: 'page'` marks the chat column (`data-variant="page"`) for a page's own full-page styling, and `activity` adds a row under the thread that shows the page's own line or the peer's current step while it runs. Both are off by default, so the story chat is unchanged.
- **`kit.chat` takes a page's own words and rules.** `mount` accepts `copy` (a page's words over the chat's), and a `target` can set which row is live (`pick`), which handles count as the peer's side (`handles`), which mailboxes the thread reads (`sources`, each read on its own, with unread and stale rows and Retry), and how a launch binds (`bindLaunched`, `keepUnsent`). The handle also gains `post`, `threadFailed` and `threadSettled`. Without these options the chat behaves as before.
- **A page's `kit.chat` can replace a pin at the cap, as an agent's chat overlay does.** With `onPin.replace`, Pin at 3 of 3 becomes Pin…, which opens a chooser under the message. It lists the pins in order, with who pinned each and when. Choose one with the arrow keys and Enter, or a click, and the message takes that pin's place. One Undo brings both back. A pin the agent adds while the chooser is open is marked New and must be chosen twice. If a pin leaves, the chooser offers a plain Pin. The page's pins can mark the pin the current row would replace (`onPin.mark`).
- **`kit.chat` can send to another agent, with a control of the page's own in the composer.** A page's `target.recipient()` names who the next message goes to: Enter, Send, a page chip or `post` then sends straight to that agent instead of the chat's own peer, never starting it; a chip from the peer's Next line still answers the peer. The box clears only once the message is sent, shows it is busy until then, and a failed send keeps the text and says why. The person's message shows "To <name>" in its meta line, as real text a screen reader hears, and its text is left as typed. `layout.composerSlot` gives the page a place above the box for its own control (a "To" chip), mounted once and released on unmount, `layout.composer` can now name the input per recipient with `label`, and the mount's `repaint()` shows a change the page made. Pages that leave these unset are unchanged.
- **A page can keep the chat's send state across a hide and a show.** `kit.chat.createSendState` makes the state (the messages with their marks, the outbox, the launch's timers and the cards answered from the page), and `mount` takes it as `send`: the mount attaches to it and detaches on unmount, and while no chat is mounted the state still hands a held message to a lead that joins. Without `send`, a mount makes its own state and ends it on unmount, as before.
- **A page's `kit.chat` working row shows what the lead is writing.** With the working row on (`activity`), the row shows the live lead's latest prose from its session as it streams, one line long, with the whole chunk on hover. It clears when the turn ends or the lead's next message arrives. Screen readers hear "Working…" once, not every chunk. A session the host can't stream (another machine or another CLI) shows the row as before.
- **One chat for dashboard pages.** The dashboard kit now has `kit.chat` (load `/kit/v1/chat.js` after the kit): `kit.chat.mount(el, { transport, reads, layout, cards, headerSlot, chips })` draws a chat with Queued and Delivered marks, inline needs-you cards with option buttons, and a log that opens at the newest message and follows new ones only while you are at the bottom. The marks rule and the card parser are also served as a DOM-free module at `/kit/v1/chat-core.js`. The app re-exports the same module with types from `src/features/inbox/lib/chat-core.ts`.
- **Dashboards can list the installed agent CLIs.** `kit.runtimes()` returns the CLIs on this Mac in the order a page should offer them: the last used one, then Claude, Codex and OpenCode. Hermes is listed but never picked for you. While the app is still looking for the CLIs on first launch, it says so, so a page can wait instead of showing none.
- **Linux updates.** The Linux AppImage now updates itself in place, after the same signature check as on macOS; a `.deb` or `.rpm` install says to update through your package manager instead.
- **Line attribution on Linux.** Linux builds (x86_64 and aarch64) now include git-ai and turn line attribution on, fetched for each target from a checksum-pinned git-ai release.
- **Key passphrases on Linux.** Adding a machine with "Key + passphrase" now works on Linux: a system dialog (zenity, kdialog or your `SSH_ASKPASS` program) asks for the passphrase, and CodeSense keeps it in Secret Service so you aren't asked again. The passphrase never enters the app's window.
- **The managed starship prompt on Linux.** Linux builds (x86_64 and aarch64) now include CodeSense's managed starship prompt, fetched for each target from a checksum-pinned starship release.
- **Linux test builds.** Maintainers can dispatch the Test build workflow for Linux to get an unsigned `.deb`, `.rpm` and AppImage; the bundled git-ai is left out on Linux for now.
- **The terminal server's tray icon and keep-running-in-background on Linux.** With the AppIndicator library installed, **Show terminal server in the tray** puts the terminal server's status, Open CodeSense, Restart, Stop or Start and Quit in the tray, and while it shows, closing the window keeps CodeSense running and the icon's menu brings it back; with no tray icon, closing the window quits as before.
- **Pages see each sent message's delivery pushed.** A message a page sends an agent with `sendAsHuman` gets a row on the new `messageDelivery` live topic, keyed by its message id: `queued`, then `delivered` once the agent is told about it (its inbox notice was confirmed). Delivered means told, not read. Inbox rows carry `toldAtMs`.
- **Pack format.** CodeSense now has a typed model and JSON Schemas for `pack.yml` and `packs.lock.yml`, the files that describe an installable pack.
- **pack_validate.** A new read-only MCP tool checks a pack folder against the pack format and reports the risk facts derived from its files.
- **A page reads an agent's whole thread.** `inbox({agentId, storyId, sessionId})` reads the messages of every session of a saved agent on a story, an ended predecessor's included, with `sessionId` as the seat whose concurrent sessions stay out; a page tests for it with `codesense.has("inboxThread")`.
- **Pages can read the setup and hear when it changes.** `setupState()` returns this Mac's orgs, teams and source repos, read-only, and a page gets one `codesense:setup-changed` message after any change to them, such as a team created or deleted, a context repo attached or a source repo added.
- **Choose the model for an agent you launch with `open_workspace`.** The MCP tool takes a `model`, passed to the agent's CLI as `--model`. Bundled pages can also open a team workspace through a new narrow grant that no page holds yet.
- **Open the story dashboard from the command palette.** The command palette has a Story dashboard row, so the focused story's dashboard opens on Linux and Windows, where there is no View menu.
- **Export to PDF on Linux.** Markdown and HTML documents export to PDF on Linux, from the tab menu, the file tree's right-click menu and Ctrl+Shift+E, on US Letter pages with the usual margins. Exporting a canvas as PNG or SVG now works on Linux and Windows too.
- **Pin at the cap by choosing which pin to replace.** When an agent's chat already shows 3 pins, a message's Pin… opens a short list of the pins under it. Choose one, and the message takes that pin's place; one Undo puts both back. A pin the agent added while the list is open must be looked at before it can be replaced, and a pin that leaves meanwhile turns the list into a plain Pin.
- **Replace a pin at the cap in one step.** A page can pin a message in place of a pin it names with the `replacePin` verb, even when a thread already shows 3 pins; the new pin takes the old one's place, and `restorePin` with `replacing` undoes it, bringing the old pin back as it was. A replace of a pin that left in the meantime is refused and changes nothing. An agent's own pin tool still refuses a fourth pin.
- **probe_environment.** A new read-only MCP tool reports which agent CLIs, git and the GitHub CLI are installed, whether `gh` is signed in, whether a folder is a git repository and whether named environment variables are set in your login shell (zsh or bash; for another shell they read as unknown). It never returns a token or a variable's value, and it does not look inside Documents, Desktop, Downloads, cloud storage folders or an external volume unless you attached that folder, even through a link.
- **A remote worktree's changed images show Before | After.** In the source diff of a worktree on another machine, a changed PNG, JPEG, GIF or WebP now draws its two sides, as a local one does. They are read through the machine's Git, a side whose bytes aren't such an image is refused, and a side past the 8 MB cap stays Source only.
- **Rendered Before | After for changed HTML, SVG and Excalidraw files off Files.** The source diff, the open-diff tab and Unsaved team edits show a changed `.html`, `.svg` or `.excalidraw` file rendered side by side at 900 px and wider, with a Before | After toggle below that, and keep Source mode. Each side is drawn from its own content in a sandboxed frame with no origin and a content security policy that blocks every network and file load, so linked stylesheets and images are not loaded there (the diff says so), and a side from another machine reads only its own content.
- **Rendered Before | After for changed PNG, JPEG, GIF and WebP images off Files.** The source diff (working tree and commits), the open-diff tab and Unsaved team edits now show a changed raster image's two versions side by side at 900 px and wider, with a Before | After toggle below that. Source mode keeps the binary note. Each surface reads the image's bytes through a read-only, path-checked read that serves only those four types, refuses symlinks and paths that resolve outside their repository or worktree, and stops at 8 MiB a side. A larger image, or one in a source worktree on another machine, stays on the binary note.
- **Role queues show which message a reply answers.** `role_state` lists each delivery's `inReplyTo`, and the full text (up to 4000 characters) of each one still waiting, so an agent working a role queue can match a reply to its card without a second read.
- **Seat worktrees clean themselves up.** When a seat's tab or its workspace is closed, and in a background sweep after each launch into the story, a seat worktree is removed with its seat branch and its git-ignored files (installed dependencies, build output, any local ignored files) once no session runs in it, it is clean, its context edits are published and its commits are in the story branch; otherwise it is kept and its `list_worktrees` row says why (`seatKept`). An agent Relaunch whose folder is gone is now refused instead of starting in the story's base worktree.
- **A session record sums the handoff chain.** When a saved agent handed a story off from earlier sessions, `codesense.sessionRecord({handle})` adds their tokens, cost, duration and files into the record and lists the chain's session ids in `chain`, so a page can show "N sessions".
- **An agent's session record for pages.** A dashboard can read one agent's model, tokens, cost, duration, changed files and story with `codesense.sessionRecord({handle})`, and re-read it on `onSessionRecordChanged`, which a page can limit to its own agent's session with the record's `sessionIds`. A model with no rate no longer blanks the cost: `costUsd` is the priced part and `unpricedModels` names the rest. The record refreshes on the agent's progress, done and exit and about 2 s after usage is stored for its session; commits have no event of their own. The figures are the ones `session_usage` and `story_changes` report for that session.
- **Pages can hear a Claude agent's reply as it is written.** `codesense.onSessionText(sessionId, cb)` streams a local Claude session's assistant prose to a page as each block lands, then exactly one final message per turn, without waiting for the conversation capture. Tool calls, tool output and the model's thinking are never sent, and each line is redacted as the stored conversation is. A page needs the `sessions:read` grant and hears only sessions of its own team.
- **A story file opens its team's story page.** A team can name a story page in `teams.yml` (`story_page:`, relative to its content). An `.md` file whose front matter says `type: story`, `bug` or `spike` then opens that page in the file's own tab, with the file named in the page's URL fragment, from the Files tree, a pipeline card, a link in a viewer or an inbox file chip. Opening it again focuses the tab. A team without the setting opens such a file as markdown, with a line saying why.
- **A named story session can have its own worktree.** `open_workspace` takes `seatWorktree`: `{kind:"branch"}` gives the session a writable worktree on its own branch cut from the story branch, and `{kind:"commit", commit}` a detached checkout pinned to that commit with no setup; without it every session of a story still shares the story's worktree.
- **View → Dashboard opens the focused story's dashboard.** The item opens the story of the focused workspace, or the story file in the active tab, in its team's story page. With no story in focus it says so, and when the team has no story page it says that its story opens as markdown.
- **Agent tabs on Windows start the agent directly.** Every agent launch there runs the agent as the tab's own process instead of typing a command into a shell, refuses a `.cmd` or `.bat` launcher, and recognises `claude.exe` and npm's `node.exe … cli.js` as the running agent.
- **Keep running in the background on Windows.** On Windows the terminal server's icon can now show in the notification area (**Show terminal server in the tray** in Settings → General), and while it shows, closing the window keeps CodeSense running instead of quitting; **Open CodeSense** in the icon's menu brings the window back.
- **See worktree docs rendered.** Markdown, images and canvases in a source worktree, and the HTML dashboards your team's context brings into it, have a Rendered | Source switch, so story docs and dashboards read as they render, with `window.codesense` working in the dashboard. A dashboard renders only when it came from your team's context, and never reaches the outside network; the repo's own HTML opens as text. Images and canvases open rendered, as do story docs and dashboards; the app remembers your choice per file type, separately for team context and the rest of the worktree. ⇧⌘V switches between the two, and a canvas you draw on saves into the worktree.

### Changed

- Lower idle CPU while agents work: the inbox re-reads only when mail, a team or the sessions it shows change, and agent activity alone no longer tells inbox views to refresh.
- **Machine saves never overwrite a newer edit.** Saving a machine is refused if it changed since you opened it; reopen it and save again. Over MCP, `save_machine` now needs `declarationRevision` (the `declaration.revision` from `list_machines`) to change a legacy machine you can publish, personal or shared.
- **A refused switch to a private account keeps your connection.** CodeSense makes every check it can before ending the machine's current connection.
- **Private machines changed elsewhere say so.** One clear message shows on save, connect and the machine list, and only that machine is affected. Renaming a personal private machine now saves; renaming a team private machine is refused, since every teammate's setup shares its name.
- Mark unread on a conversation now marks only its newest message to you, and the inbox menus use one short wording.
- **The overlay's Full view opens the team's agent page.** A team names its agent page in `teams.yml` (`agent_page:`, relative to its content, with the same path rules as `landing_page`); Full view opens that page for the session, in the agent's team. A team without the setting shows no Full view button.
- **Features that aren't on your OS yet say so.** Where remote machines or agents' CodeSense tools aren't available on the OS, Machines and the launch sheet now explain why instead of failing, and off macOS the title bar no longer leaves room for the macOS window buttons.
- **Agent tabs open on their chat.** A tab you launch as an agent now opens on its chat, covering the terminal, with a Chat | CLI switch in the tab's caption (⌘I flips it too). The CLI keeps every line while the chat shows: the switch says how many new lines it holds, and takes the needs colour with "Input needed" when the CLI is waiting on a permission prompt, a startup screen or a question, with a Show CLI line in the chat. Plain shell tabs, and a CLI you start by hand, stay on the terminal. The chat no longer docks beside the terminal on wide tabs: it always covers the tab.
- **Queued and Delivered follow each message's own delivery.** The chat overlay and pages that mount the kit's chat (through `reads.delivery`) now mark a message you sent from its own `messageDelivery` row, which turns delivered when the agent is told or reads it. A host without the topic keeps the marks as before.
- **An agent's chat thread is one Tab stop.** In a tab's chat overlay and the Agents pane chat, Tab stops on one message at a time (the newest, until you move) and on that message's own actions, not on every message's Pin. Up and Down move between messages, and Home and End go to the first and the newest. Focusing a message's Pin, its note or its Undo makes that message the stop, so the at-cap note and Undo stay where you acted.
- **Claude's hooks run the bridge.** The status hook and the secret-file guard are now `codesense-bridge hook` subcommands, written in the form each host runs (PowerShell on Windows, which needs Claude Code 2.1.295 or newer), so they need no bash, curl or Perl; settings an earlier CodeSense wrote are updated in place.
- **Default terminal shell on Linux.** When your own shell can't be used, terminals on Linux now start `/bin/bash`, then `/bin/zsh`, then `bash` on your `PATH`, and command lines for fish users run under bash. Settings → Terminal shell names the shells your OS accepts.
- **Diffs match across views.** Markdown, HTML and code changes now open the same way in Files, the source diff, the open-diff tab and Unsaved team edits, and the mode you pick carries across them.
- **Setup on first launch.** A new install opens the CodeSense setup page instead of the Foreman or the README, and "Set up CodeSense" in the identity menu and the command palette reopens it.
- **The Foreman's terminal tab chats like its page.** The chat overlay on a Foreman session shows the Foreman page's thread (earlier Foreman sessions' messages too, oldest first) and the page's pins, and its Full view opens the one Foreman tab even though the docs team declares no agent page. A message sent from either shows in both.
- **Docs reference data built with the app.** The bundled docs' search index and reference data (primitives, recipes, schemas, UI and MCP cross-reference) are now generated when the app is built, so they always match the shipped version.
- **Dependency status includes the GitHub CLI.** The app's dependency status now reports whether `gh` is installed and its version, next to git, found in the background after launch like the agent CLIs so startup never waits on it; Codex, OpenCode and Hermes also read as detecting, not as not installed, until that search finishes.
- **Hidden terminals pause output parsing.** Parked terminals buffer output and replay it when shown, reducing idle CPU use in workspaces with many sessions.
- **The Inbox pane stays light while agents are busy.** New mail shows at once when things are quiet. During a burst of inbox changes the pane refreshes about once a second, so new mail shows within about a second plus the time to read it. Reading, reacting to or archiving your mail elsewhere usually shows within a quarter second, and actions you take in the pane never wait. While the pane is hidden it only keeps its badge current, and session changes no longer make it re-read.
- **A `kit.chat` needs-you card shows why the lead picked its answer.** When the lead gives a reason with its pick ("My pick: Ship, because green."), the card now says "Story lead recommends Ship because green." under the question, before the answers. Before, only the question and the recommended mark showed.
- **`kit.chat` draws simple formatting in messages.** A message's `**bold**`, `*italic*` or `_italic_`, and `` `code` `` now show as such, instead of their raw markers. Only that small set is read. Names like `snake_case`, sums like `2*3*4`, and markers left open stay as written, and a tag in a message is still shown as text. HTML messages are unchanged.
- **A page's `kit.chat` thread is one Tab stop, as an agent's chat overlay is.** Tab stops on one message at a time (the newest, until you move) and on that message's own actions, not on every message's Pin. Up and Down move between messages, and Home and End go to the first and the newest. Focusing a message's Pin, note or Undo makes that message the stop. A thread with no messages yet stays a Tab stop itself.
- **The agent chat composer is one two-row box.** On agent pages the message box holds the text on top and its hint and Send under it. Enter sends and Shift+Enter starts a new line; ⌘↵ (Ctrl↵) sends too, with Shift held as well. On a short or narrow pane it falls back to one line beside Send, and the Enter that confirms an input-method candidate no longer sends.
- **The Linux `.rpm` names the WebKitGTK and GTK packages it needs.** It now requires `webkit2gtk4.1` and `gtk3` by package name, beside their libraries, as the `.deb` already did.
- **Linux windows no longer open blank in virtual machines.** The app now turns off the WebKitGTK DMABUF renderer at startup unless you set `WEBKIT_DISABLE_DMABUF_RENDERER` yourself.
- **Lighter live updates.** A change to a session, a preference or another live row now reaches the app as just the fields that changed, and views nothing has open receive no updates at all, so the app does less work while it sits idle.
- **macOS bundles git-ai 1.7.5-cs.7.** The macOS app now ships git-ai 1.7.5-cs.7, a Developer ID signed and notarized build checked against its release's published SHA256SUMS; line attribution works as before.
- Manual update downloads open the download page for the build's channel.
- **An agent's chat with no story counts its sessions as its thread does.** A saved agent's sessions with no story share one thread: its pins, its messages and now its session record. The record sums the agent's listed sessions with no story that have ended, as its thread shows their messages, instead of counting one; two sessions still running are each their own, and neither counts the other.

## [0.1.0] - 2026-11-06

The first public release of CodeSense. CodeSense is a Mac app that runs your team of Claude Code, Codex and OpenCode agents across every repo, all in your own git. It needs macOS on Apple Silicon. You run Claude Code, Codex or OpenCode with your own subscriptions and settings; CodeSense never calls a model itself.

### Added

- **A worktree for every story.** Open a story and CodeSense makes its worktree in the story's own repo, on its own branch, and starts the agent there. Open it again and you're back where you left off.
- **Your team's context in every worktree.** Skills, CLAUDE.md, AGENTS.md and any other files your context names land in each agent's worktree when it launches, as real files hidden from git.
- **Skills that get better.** Improve a skill in any worktree and have an agent sync it back to your team's context. The next agent you launch starts with the better version.
- **Plans are plain files.** Stories are Markdown with frontmatter, or HTML pages. Status, sprint and dependencies are fields in the file, and the sidebar marks a story ready once everything it depends on is done.
- **An inbox for every agent.** Your agents message each other and you. Only what waits on you lands in Needs you; progress goes to Updates. When an agent needs a decision, it asks you and waits.
- **One list of every agent.** See every running agent, who launched it, where it runs and which ones need you. Press ⌘\ from anywhere to bring it back.
- **Live status.** Claude Code, Codex and OpenCode sessions show whether they're running, waiting on you or done, whether CodeSense launched them or you typed them by hand.
- **Saved agents.** Save Claude Code, Codex or OpenCode with your flags, MCP servers, permissions, an avatar and a starting prompt. Launch it in a terminal or headless.
- **Review over the terminal.** The diff and a code editor float over the agent's terminal while it keeps working. ⌘⇧D shows the change; ⌘⇧C opens the file so you can fix a line yourself.
- **Agents keep running when you quit.** Open CodeSense again and every terminal is where it was.
- **Remote machines.** Run Claude Code and Codex agents on a Linux machine over SSH, with the same tools, the same inbox and your team's context.
- **Routines.** Run an agent on a schedule or when mail arrives. A routine wakes the agent that's already running instead of starting a second one.
- **Live pages and dashboards.** Any HTML file in your context is a live page beside your plans. Ask an agent for a dashboard and it writes one over your stories, agents and usage.
- **The whole app over MCP.** Your agents can open workspaces, run and read terminals, message each other and you, and query your context.
- **Cost per story.** Every Claude Code, Codex and OpenCode session CodeSense launches records its tokens and spend, and the story, agent and model it was spent on.
- **Who wrote each line.** When a Claude Code or Codex agent commits from a CodeSense worktree on your Mac, each line it added links back to the session that wrote it.
- **Your git, your rules.** CodeSense never commits, pushes or merges. Your agents do the git, with your own keys, hooks and branch protections.

### Privacy

- CodeSense checks for updates automatically. The check names only your Mac's platform; it sends no account, version or usage data. There's no sign-in and no usage tracking.
- When you share a dashboard, the CodeSense operator sees the email addresses of the people you invite before the invites are sent. See [Privacy and network calls](https://github.com/codesensehq/codesense/blob/main/PRIVACY.md#11-publishing-a-dashboard-sharecodesenseai).

### Security

- CodeSense's background terminal service accepts connections from programs running under your Mac user account, and from no other user. CodeSense trusts what runs as you; see [How CodeSense trusts agents](https://github.com/codesensehq/codesense/blob/main/SECURITY.md#how-codesense-trusts-agents).

### Known limitations

- CodeSense runs only on Macs with Apple Silicon. There is no Intel Mac, Windows or Linux desktop build.
- CodeSense is tested on macOS 26 (Tahoe); older versions may work.
- Routines you set up on your Mac run only while CodeSense is open.
- Live status and inbox delivery work with Claude Code, Codex and OpenCode. Other command-line agents run in a worktree terminal and read your context; full support for more agent CLIs is coming.
- OpenCode (2.1.4 or a newer 2.x release) runs on your Mac only. Remote machines and line attribution work with Claude Code and Codex. CodeSense starts OpenCode with its own config folder, so your `opencode auth login` logins and a repo's `opencode.json` apply, but `~/.config/opencode` doesn't.
- There's no button to open a pull request. Ask your agent to do it.
- There's no company sign-in, roles or central audit log.
- A running agent sees changes to your team's context only when it asks for them. New agents get the latest when they launch.
- A story changes one repo. To change two repos, write one story for each.

### Known issues

- When you edit the label of a private remote machine and save, CodeSense says it saved, but the old label stays.
- If you build CodeSense from source in a folder whose path contains the word "resolve", one of the project's own checks fails. Build from a different folder.
